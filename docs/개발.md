# 개발

저장소에서 sonbae를 고치거나 데이터를 다시 만들 때 보는 문서다. 사용자용 설치·사용법은 [README](../README.md)에 있다. 전체 문서와 진행 현황은 [허브 문서](README.md)에서 시작한다.

## 기본 명령

```bash
uv sync           # 의존성 설치
uv run pytest     # 테스트
uv run ruff check # 린트
```

## 데이터 파이프라인

```bash
uv run python -m pipeline.collect all          # 원문 수집 → data/raw/ (블로그 이름으로 골라 받기 가능)
uv run python -m pipeline.extract <블로그>     # 구조화 → data/entries.jsonl (OpenAI API 키 필요)
uv run python -m pipeline.normalize            # 기술 사전에 없는 이름 리포트
uv run python -m pipeline.expand               # 문서 확장 → data/expansions.jsonl (OpenAI API 키 필요)
uv run python -m pipeline.embed                # 항목 임베딩 → data/embeddings.npz (Voyage API 키 필요)
uv run python -m pipeline.build_index          # 검색 DB → data/techblog.sqlite
uv run python -m pipeline.release_db --upload  # 검색 DB를 GitHub Release로 배포 (gh 로그인 필요)
uv run python -m pipeline.update               # 새 글만 수집→추출→확장→임베딩→빌드 (매주 GitHub Actions가 실행)
```

OpenAI·Voyage API 키는 `.env.example`을 `.env`로 복사해 `OPENAI_API_KEY`, `VOYAGE_API_KEY`를 넣거나 환경 변수로 설정한다. 서버(`sonbae`)는 `.env`를 읽지 않으므로 서버의 키는 클라이언트 등록 때 환경 변수로 넣는다.

## 저장소 코드로 서버 실행

저장소의 `data/techblog.sqlite`를 쓴다.

```bash
claude mcp add sonbae -- uv run --directory "<저장소 절대 경로>" sonbae
```

### 원격 서버(Streamable HTTP)로 실행 (M9)

같은 도구를 HTTP로 제공한다. 기본은 `127.0.0.1:8000`이고 `SONBAE_HOST`, `PORT` 환경 변수로 바꾼다(컨테이너에서는 `SONBAE_HOST=0.0.0.0`). MCP 주소는 `/mcp`다.

`SONBAE_TOKEN`을 설정하면 `Authorization: Bearer <토큰>` 헤더가 맞는 요청만 받고 나머지는 401로 거절한다. 토큰 없이 로컬이 아닌 주소로는 기동하지 않는다. `GET /health`는 준비가 끝나면 200, 준비 중·실패면 503이고 토큰이 필요 없다. 요청은 토큰 버킷으로 제한한다(기본 분당 60회·몰림 20회, `SONBAE_RATE_PER_MINUTE`·`SONBAE_RATE_BURST`). 넘으면 429와 `Retry-After`를 돌려준다. 로그는 JSON 한 줄씩 표준 출력에 쓴다(`http_request`, `tool_call`, 같은 요청은 `request_id`로 묶음, 검색어 원문은 남기지 않음). 서버는 `.env`를 읽지 않으므로 Voyage 키는 `--env-file .env`처럼 환경 변수로 넣는다.

```bash
uv run sonbae-http
```

```bash
claude mcp add --transport http sonbae-http http://127.0.0.1:8000/mcp --header "Authorization: Bearer <토큰>"
```

### 컨테이너로 실행

`Dockerfile`은 서버 의존성만 설치하고(dev·pipeline 그룹 제외) 검색 DB는 기동 때 Release에서 받는다. 컨테이너 안에서는 `0.0.0.0:8080`으로 열려 토큰이 필요하다.

```bash
docker build -t sonbae-remote .
```

```bash
docker run --rm -p 8080:8080 -e SONBAE_TOKEN=<토큰> -e VOYAGE_API_KEY=<키> sonbae-remote
```

### Fly.io 배포

설정은 `fly.toml`에 있다(도쿄 리전, 1GB, 요청이 없으면 멈추고 요청이 오면 켬, `/health` 확인). 앱 이름 `sonbae`가 이미 쓰이고 있으면 `fly.toml`의 `app`을 바꾼다. 처음 한 번 앱을 만들고 시크릿을 넣은 뒤 배포한다.

```bash
fly apps create sonbae
```

```bash
fly secrets set SONBAE_TOKEN=<토큰> VOYAGE_API_KEY=<키>
```

```bash
fly deploy --ha=false
```

`--ha=false`가 없으면 첫 배포 때 이중화로 머신을 2대 만든다. 연결 주소는 `https://<앱 이름>.fly.dev/mcp`다. 토큰을 `.env`의 `SONBAE_TOKEN`에 두었다면 `grep -E "^(SONBAE_TOKEN|VOYAGE_API_KEY)=" .env | fly secrets import`로 값을 화면에 내지 않고 시크릿을 넣을 수 있다. 로그는 `fly logs`, 직접 끄고 켜려면 `fly machine stop`·`fly machine start`.

#### 자동 배포 (GitHub Actions)

첫 배포 뒤에는 `.github/workflows/deploy.yml`이 배포한다. main에 서버 코드(`src/`, `Dockerfile`, `fly.toml`, `pyproject.toml`, `uv.lock`)가 바뀌면 CI(린트·테스트)를 거쳐 `fly deploy`하고, `/health`와 도구 호출(`aggregate`에서 지금 있는 항목 ID를 받아 `get_details`로 상세가 오는지)로 확인한다. 확인이 실패하면 직전 배포의 이미지와 `fly.toml`로 되돌리고 `deploy` 라벨 이슈로 알린다. 데이터만 바뀐 병합(주간 갱신 PR, `src/sonbae/db_release.json`)은 배포하지 않는다(서버가 기동할 때 최신 DB를 받는다). Actions 탭의 "원격 배포"에서 수동으로도 실행할 수 있다(main만).

저장소 시크릿 두 개가 필요하다. 배포 토큰은 `fly.toml`의 앱 하나의 배포 권한만 가진다.

```bash
fly tokens create deploy -a "$(sed -n 's/^app = "\(.*\)"/\1/p' fly.toml)" | gh secret set FLY_API_TOKEN
```

```bash
grep -E "^SONBAE_TOKEN=" .env | cut -d= -f2- | gh secret set SONBAE_TOKEN
```

## 옛 이름에서 옮겨 오기

2026-10-14에 이름이 `techblog-mcp`에서 `sonbae`로 바뀌었다. 옛 이름으로 설치했다면 `uv tool uninstall techblog-mcp`로 지우고 README의 설치·등록을 다시 한다. 옛 검색 DB 폴더(`techblog-mcp`)는 더 쓰지 않으니 지워도 된다. 환경 변수도 `TECHBLOG_MCP_*`에서 `SONBAE_*`로 바뀌었다.
