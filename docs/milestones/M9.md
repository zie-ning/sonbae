# M9. 원격 HTTP 서버 (확장)

> 상태: **진행 중** · 직무 근거: 백엔드 · 허브: [docs/README.md](../README.md)

M8의 데이터 배포 구조를 재사용하므로 M8 다음에 한다.

## M8에서 넘어온 항목

- **DB 준비**: 원격 서버도 M8 4단계 방식(`db.cached_db`, `db.check_for_update`)으로 최신 Release DB를 하루 한 번 확인해 받는다. ~~원격 서버는 오래 떠 있으므로 실행 중 교체가 필요한지 착수 시 정한다~~ → 서버를 필요할 때만 켜고 꺼서 실행 중 교체는 하지 않는다 ([기획.md](../기획.md#원격-http-서버-m9))
- **PyPI 전환 보류의 전제**: 설치 없이 URL로 연결하는 원격 서버가 설치 편의 문제를 해결한다는 판단으로 PyPI 전환을 보류했다 ([기획.md](../기획.md#배포-로드맵))

## 작업

- stdio는 유지하고 Streamable HTTP 방식을 추가해 클라우드에 배포
- 요청 제한, 구조화 로깅, 지연 시간 모니터링

## 완료 기준

URL만으로 연결해 쓸 수 있음.

## 결정

- 호스팅은 Fly.io(shared-cpu-1x 1GB), 실제 사용자를 받지 않고 필요할 때 켜고 끈다 (2026-10-18, [기획.md](../기획.md#원격-http-서버-m9))
- 서버가 Voyage 키를 보관하고(Fly.io 시크릿), 토큰 하나를 `Authorization: Bearer`로 확인한다 (2026-10-18, 같은 곳)
- 요청 제한은 프로세스 메모리의 분당 한도(넘으면 429), 상태 없는 세션(`stateless_http`)과 `GET /health`(준비 전 503)를 두고, DB는 기동 때 최신 Release를 받는다 (2026-10-18, 같은 곳)

## 진행 기록

### 착수 분석 (2026-10-15~18)

- SDK(mcp 2.2.0)의 `MCPServer.run()`이 `transport="streamable-http"`, `stateless_http`, `host`/`port`를 지원해 전송 방식 추가는 작다. 도구 호출마다 DB 연결을 여는 구조(#22)라 동시 요청에도 안전하다
- 준비를 마친 서버는 메모리 약 590MB, 준비 7초(로컬 Windows 측정). 512MB 등급은 부족하다
- 착수 결정은 모두 정했다(위 "결정"). 다음은 구현

### 1단계: HTTP 진입점 (2026-10-18)

- `sonbae.remote`와 명령 `sonbae-http` 추가. `server.py`의 도구를 상태 없는 Streamable HTTP(`/mcp`, JSON 응답)로 연다. 주소는 `SONBAE_HOST`(기본 127.0.0.1)·`PORT`(기본 8000)
- 테스트(`tests/test_remote.py`)는 실제 uvicorn을 띄우고 MCP 클라이언트로 URL에 연결해 도구 목록·검색 결과가 stdio 호출과 같은지, 동시 연결 8개가 섞이지 않는지 본다
- 실제 DB로 띄워 URL로 연결해 검색까지 확인(연결·목록·검색 0.2초)

### 2단계: 토큰 인증 (2026-10-18)

- `remote.TokenAuth` ASGI 미들웨어: `SONBAE_TOKEN`이 있으면 `Authorization: Bearer <토큰>`이 정확히 맞는 HTTP 요청만 통과, 나머지는 401과 `WWW-Authenticate: Bearer`. 상수 시간 비교(`hmac.compare_digest`). 응답 스트림을 막지 않도록 BaseHTTPMiddleware가 아니라 ASGI로 직접 감쌌다
- 토큰 없이 로컬이 아닌 주소로 열면 DB 준비 전에 기동을 멈춘다
- 테스트: 토큰 없음·틀림·형식 오류(`Bearer` 없음, `Basic`) 401, 맞는 토큰으로 MCP 클라이언트 검색, 토큰 없는 외부 기동 거부. 실제 기동에서도 curl로 401·401·200과 기동 거부를 확인

### 3단계: 요청 제한 (2026-10-18)

- `remote.TokenBucket`과 `remote.RateLimit` ASGI 미들웨어: 인증을 통과한 `/mcp` 요청을 토큰 버킷(기본 분당 60회, 몰림 20회)으로 세어 넘으면 429와 `Retry-After`. 미들웨어 순서는 인증 → 요청 제한 → MCP라 틀린 토큰은 세지 않는다. 이벤트 루프 안에서 await 없이 세므로 잠금은 두지 않았다
- 테스트: 가짜 시계로 몰림·다시 참·쉬어도 몰림 이상으로 쌓이지 않음, 실제 서버로 한도 초과 429·`Retry-After`, 틀린 토큰이 한도를 쓰지 않음
- 추천값 실험(실제 기동, 로컬):

| 실험 | 결과 |
| --- | --- |
| 즉시 30회 몰림(`tools/list`) | 20회 성공, 10회 429 (몰림 허용만큼 통과) |
| 에이전트 패턴: 연결 하나로 검색 5개 병렬 × 3번(실제 Voyage) | 15회 모두 성공, 단어 일치 대체 0, 3.7초 |
| 초당 2회 30초 지속 | 49회 성공, 11회 429 (처음 차 있던 20 + 초당 1개씩 30) |

- 연결 하나로 부르면 검색 하나가 HTTP 요청 하나로 세진다(연결할 때 initialize 등 1~2회 추가)
